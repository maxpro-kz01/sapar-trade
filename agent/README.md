# Агент синхронизации 1С → Sapar Trade

Скрипт PowerShell, который работает на сервере 1С (`srv1c`). Раз в 5 минут он **читает** данные из базы `utp` и отправляет их на сервер Sapar Trade.
- В 1С ничего не меняет: только запросы на чтение, отдельный пользователь `sapar_api`.
- Порты наружу открывать не нужно: агент сам отправляет данные по HTTPS.
- Пароль 1С и ключ агента хранятся зашифрованными (Windows DPAPI). Расшифровать их может только тот же пользователь Windows на этом сервере.

## Что передаётся
| Тип | Откуда в 1С | Как часто |
|---|---|---|
| `stock` остатки | РегистрНакопления.ТоварыНаСкладах (остатки сейчас) | 5 мин |
| `prices` цены | РегистрСведений.ЦеныНоменклатуры (срез последних, все типы цен) | 5 мин |
| `sales` продажи | РегистрНакопления.Продажи, обороты по дням за последние 3 дня | 5 мин |
| `cost` себестоимость | РегистрНакопления.ПродажиСебестоимость, по дням за 3 дня | 5 мин |
| `debts` долги клиентов | РегистрНакопления.ВзаиморасчетыСКонтрагентами (договоры с покупателями) | 5 мин |
| `products` товары | Справочник.Номенклатура | 60 мин |
| `clients` клиенты | Справочник.Контрагенты (покупатели, основной менеджер, телефон, адрес) | 60 мин |
| `warehouses` склады | Справочник.Склады | раз в сутки |

Тексты запросов лежат в папке `queries\`. Если в вашей базе объект называется иначе, запрос правится там, без изменения скрипта.

## Установка (делает администратор или специалист 1С, примерно 30–40 минут)

**0. Сделайте резервную копию базы 1С.**

**1. Пользователь 1С только для чтения.** В Конфигураторе: Администрирование → Пользователи → добавить `sapar_api`:
- аутентификация 1С:Предприятия с надёжным паролем;
- роли: только просмотр данных и право внешнего соединения. Набор ролей в УТП 2.0 зависит от вашей базы, подберите их сами;
- проверка: войдите под `sapar_api` и убедитесь, что провести или изменить документ нельзя.

**2. COM-компонента 1С.** В командной строке от администратора (путь — к вашей версии платформы):
```
regsvr32 "C:\Program Files\1cv8\8.3.23.2040\bin\comcntr.dll"
```
Разрядность должна совпадать: 64-битная платформа требует 64-битного PowerShell (обычный), 32-битная — `C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe`.

**3. Пользователь Windows для агента** (например `sapar_agent`, обычный, не администратор). Под ним будет работать задание планировщика.

**4. Папка агента.** Скопируйте папку `agent` в `C:\SaparTrade\agent`. Затем скопируйте `config.example.json` в `config.json` и проверьте:
- `serverUrl` — адрес сервера (даёт разработчик);
- `onec.server` = `srv1c`, `onec.base` = `utp`, `onec.user` = `sapar_api`.

**5. Секреты.** Запустите PowerShell **от имени `sapar_agent`** (Shift + правый клик → «Запуск от имени другого пользователя»):
```
cd C:\SaparTrade\agent
powershell -ExecutionPolicy Bypass -File .\sapar-1c-agent.ps1 -SetSecrets
```
Введите пароль `sapar_api` из 1С и ключ агента (выдаёт разработчик).

**6. Проверка связи** (в том же окне):
```
powershell -ExecutionPolicy Bypass -File .\sapar-1c-agent.ps1 -Test
```
Должно быть «Сервер: OK» и «1С: OK».

**7. Диагностика — отправьте файл разработчику:**
```
powershell -ExecutionPolicy Bypass -File .\sapar-1c-agent.ps1 -Probe
```
Появится файл `probe-ГГГГММДД-ЧЧММ.txt`. В нём:
- структура нужных объектов 1С;
- по 5 строк каждого запроса;
- количество строк.

Паролей в файле нет. По этому файлу разработчик сверит запросы с вашей базой.

**8. История продаж** (один раз, после проверки запросов):
```
powershell -ExecutionPolicy Bypass -File .\sapar-1c-agent.ps1 -Backfill 400
```
Загружает продажи и себестоимость за 400 дней, по месяцам. Лучше запускать вечером.

**9. Автозапуск каждые 5 минут.** PowerShell **от администратора**:
```
cd C:\SaparTrade\agent
powershell -ExecutionPolicy Bypass -File .\install-task.ps1 -User "SRV1C\sapar_agent"
```

## Проверка работы
- Журнал: `C:\SaparTrade\agent\logs\agent-ГГГГ-ММ-ДД.log`. По каждому типу данных пишется число строк и время.
- В приложении: Система управления → Интеграции. Там видно время последней загрузки. Если данные старше 15 минут, показывается «данные устарели».
- Выполнить нужные типы сразу: `.\sapar-1c-agent.ps1 -Only stock,prices`

## Если что-то не так
| Сообщение | Что делать |
|---|---|
| `Секреты не заданы` | Выполните шаг 5 **под тем же пользователем**, что в задании планировщика |
| `Класс не зарегистрирован` / `V83.COMConnector` | Шаг 2: зарегистрируйте `comcntr.dll` нужной разрядности |
| `Сервер ответил 401` | Неверный ключ агента: повторите `-SetSecrets` |
| `Сервер ответил 400: … не дата / пустой код` | Запрос возвращает не те поля: пришлите разработчику журнал и `-Probe` |
| `Поле объекта не обнаружено (…)` | В вашей базе реквизит называется иначе: пришлите `-Probe` |
| `Сервер недоступен, повтор…` | Нет интернета или сервер «просыпается» (бесплатный тариф до 1 минуты). Агент повторит сам |
| `Предыдущий запуск ещё работает` | Нормально, если изредка. Если всегда — пришлите журнал |

## Для разработчика
- Проверка без 1С: `pwsh tests/smoke.ps1 -Url http://127.0.0.1:3999 -Key test-agent-key-0123456789` (сервер — `npm run dev:local` в `server/`).
- Формат: `POST /api/sync/1c/<тип>`, тело `{ "rows": [...], "from": "ГГГГ-ММ-ДД", "to": "ГГГГ-ММ-ДД" }` (from/to только для sales/cost), `Content-Encoding: gzip`, заголовок `X-Agent-Key`.
- Колонки запросов = поля JSON: `code,name,groupName,unit,sku` / `code,name` / `code,name,manager,phone,address` / `product,priceType,price` / `warehouse,product,qty` / `client,docDate,docName,amount` / `dt,product,client,qty,revenue` / `dt,product,qty,cost`.
