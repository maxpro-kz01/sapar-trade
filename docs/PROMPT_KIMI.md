## О проекте

**ИП «Sapar Trade»** — оптово-розничная торговля продуктами и бытовой химией, **работает только в г. Кызылорда** (Казахстан). Нужна единая система:
- **Клиентское приложение** (магазины и частные лица): каталог, корзина, заказ (наличные/карта/в долг для магазинов), ежемесячный кэшбэк, сторис, баннеры, уведомления.
- **Админ-панель** (администратор склада/магазина): **смены** «Начать работу / Завершить работу» с **автоматическим полным отчётом за день директору в WhatsApp** (+7 700 105 17 17), заказы, реклама и push, склад, сторис, CRM, аудит, учётки торговых представителей, настройки.
- **Приложение торгового представителя**: мои магазины, заказ по магазину, мои заказы.
- **Система управления по ТЗ V1.0** (главная часть, см. `TZ_V1.0_RU.md`): 8+ ролей со строгими правами (владелец видит всю финансовую картину; директор — продажи, маржу %, дебиторку, команду и **GPS экспедиторов на карте**, но без валовой/чистой прибыли; остальные — только своё), Owner Dashboard «один экран», продажи и план/факт, рейтинг и Score ТП, супервайзеры, GPS, водители-экспедиторы, склад и dead stock, дебиторка, P&L, проблемы и уведомления, задачи, AI-ассистент, интеграции **1С** и **Sales Doctor**, audit log, экспорт Excel/PDF.
- **Языки: русский и казахский** (переключатель RU / ҚАЗ на всех экранах; отчёт директору — на выбранном языке).

## Что нужно сделать (по порядку)

Полный список — `STATUS_DONE_TODO.md`, раздел 2. План:

**Этап 1 — Каркас проекта**
- Монорепо по структуре из `ARCHITECTURE.md`, раздел 3: `apps/web` (Vite + React + TypeScript + Tailwind + React Router + TanStack Query + react-i18next), `apps/api` (NestJS + Prisma + PostgreSQL), `packages/shared` (типы, enum, формулы KPI), `infra` (docker-compose: postgres, redis, api, web, nginx).

- i18n: `ru.json` / `kk.json` с ключами на основе `i18n_ru_to_kk.json`.

**Этап 2 — База и авторизация**
- Миграции по `db_schema.sql`.
- Вход клиента по телефону + OTP; вход сотрудников по логину/паролю (argon2), JWT + refresh, **2FA TOTP для владельца и директора**, сессии/устройства.
- **RBAC на сервере**: guard на эндпоинты + фильтр финансовых полей в ответах (таблица прав — `ARCHITECTURE.md` §4). Это критично: права проверяет сервер, а не только интерфейс.
- Audit log.

**Этап 3 — Рабочие функции без интеграций**
- Каталог, заказы клиентов и ТП, кэшбэк, контент (баннеры, сторис, push).
- **Смены админа на сервере + автоотправка отчёта директору** (WhatsApp Cloud API или Green API; запасной вариант — ссылка `wa.me`).
- Склад, сотрудники, настройки.

**Этап 4 — Система управления на реальных данных**
- API по `API_ENDPOINTS.md`, расчёт KPI на сервере (таблица `kpi_daily`), все экраны управления, экспорт xlsx/pdf только разрешённых полей.

**Этап 5 — Интеграции**
- Воркер **1С** (OData/HTTP-сервис) и **Sales Doctor** (их API), Integration Log, кнопка «Обновить», плашка «данные устарели», алерт при сбое (ТЗ §21–24).

**Этап 6 — GPS экспедиторов по-настоящему**
- Приём координат `POST /fleet/points`, WebSocket для карты владельца и директора, треки, «нет сигнала > 5 мин», отклонение от маршрута. Приложение водителя — Capacitor с фоновым GPS (в обычном браузере GPS работает только пока страница открыта). `ARCHITECTURE.md` §7.

**Этап 7 — Остальное по ТЗ §29**
- AI-ассистент на LLM с RBAC-фильтром данных, задачи с файлами, полный склад, прогноз, мотивация, мобильные приложения, ежедневный AI-анализ.

## Важные требования
- Только Кызылорда: адреса, карта (центр 44.8465, 65.4935), часовой пояс Asia/Qyzylorda (UTC+5), валюта ₸ (формат `12 345 ₸`).
