# ТЗ: долги клиентов из 1С:Бухгалтерии (счёт 1274)

Версия 1.1 · 17.11.2026 · статус: **согласовано (17.11), сделано, ждёт подключения на сервере 1С**

## 1. Проблема
Долги на сайте брались из **УТП** (торговая база, регистр расчётов с клиентами). Бухгалтер ведёт и закрывает долги в **1С:Бухгалтерии** (ОСВ по счёту 1274). Это две разные базы, и цифры расходились в разы:

| Клиент | Бухгалтерия (1274) | Сайт (УТП) |
|---|---|---|
| B.BEGIMSULU | 153 510 | 153 510 ✓ |
| Орда су Училищная | 589 662 | 2 350 390 |
| ПИЦЦА ДОНЕР | 159 355 | 803 225 |
| Магнит ул. Абуова | 10 488 | 129 790 |
| Маг Айарыс опт Казалы | — | 17 030 846 |

**Сверка 17.11 (probe-20261117-1716, запрос 54) подтвердила причину:** за 90 дней в УТП нет ни одного приходного кассового ордера от «Орда су» и «Магнит»; у «ПИЦЦА ДОНЕР» — 31 860 ₸ и без договора. Оплаты вносятся только в Бухгалтерии, поэтому УТП показывает «вечные» долги. По видам договоров в УТП (запрос 52): с покупателем +82,3 млн, «прочее» −93,6 млн, с поставщиком −80,9 млн.

## 2. Решение
Источник долгов — **Бухгалтерия, счёт 1274** (с субсчетами, `1274%`). Мастер-источник по долгам меняется с УТП на Бухгалтерию (ТЗ V1.0 §23). Бухгалтерия стоит на том же сервере 1С, что и УТП.

## 3. Что сделано
1. **Агент 1.3.0:** второе подключение (COM) к базе Бухгалтерии. В `config.json` раздел `onecBuh` (`server`, `base`, `user`), пароль в `secrets.dat` (DPAPI, поле `buhPassword`). Настройка: `8_buhgalteria.bat` (ключ `-SetBuh`). Он спрашивает имя базы, пользователя и пароль, проверяет подключение, показывает число должников и сумму по 1274 и сразу отправляет данные. Без `onecBuh` выгрузка пропускается, остальное работает как раньше.
2. **Запрос `queries/debts_buh.1c`** (РегистрБухгалтерии.Типовой, субконто «Контрагенты»):
   - `kind = bal`: сальдо 1274 сейчас по контрагенту (Дт − Кт), как в ОСВ;
   - `kind = dt`: обороты Дт 1274 по дням за 365 дней (отгрузки), для возраста долга.
3. **Сервер:**
   - выгрузка `debts_buh` каждые 5 минут, таблица `onec_debts_buh` (миграция 007);
   - вид `onec_debts_buh_rows`: долг клиента = сальдо. Неоплаченными считаются самые новые отгрузки на сумму сальдо (FIFO). Если сальдо больше отгрузок за год, остаток идёт строкой «Долг старше года» (просрочен). Переплата даёт долг 0;
   - `onec_debts_open` (его читают все отчёты: Главная, Клиенты, Команда, Проблемы, смена) берёт данные из Бухгалтерии, если `debtsSource = buh` (по умолчанию) и данные Бухгалтерии уже пришли. Иначе берёт из УТП.
4. **Сопоставление контрагент Бухгалтерии → клиент УТП** — по названию, без учёта регистра и лишних пробелов, только если в УТП такое название одно (вид `onec_debts_buh_map`). Коды двух баз могут не совпадать, поэтому по коду не сопоставляем: ошибочно приписать долг чужому магазину хуже, чем показать его отдельно. Не найденные получают код `Б:<код>`: в сумме долгов они есть, а в настройках показаны списком.
5. **Админ → Настройки → «Откуда брать долги клиентов»:**
   - переключатель «1С:Бухгалтерия (1274) / УТП»;
   - сравнение суммы долга по Бухгалтерии с суммой на сайте, время обновления;
   - сколько контрагентов сопоставлено и список должников, которых нет в УТП (API `GET /api/settings/debts`).
6. **Папки Бухгалтерии** («Жасулан Шиели» и т.п.) не выводятся: долг считается по каждому магазину.

## 4. Проверка
- Тесты сервера `server/test/debts_buh.test.js`: пока Бухгалтерии нет, работает УТП; сальдо, FIFO, переплата, «старше года»; сопоставление по названию; переключение источника; неверные данные отклоняются. Всего тестов сервера 68, все проходят.
- Браузер `tools/apps-shots.mjs`: карточка в настройках на телефоне и компьютере.
- На месте: после `8_buhgalteria.bat` сравнить 20 крупнейших должников на сайте с ОСВ 1274. Расхождение должно быть 0, кроме тех, кого нет в УТП.

## 5. Что нужно от заказчика
- Имя базы Бухгалтерии на сервере. Его видно в окне запуска 1С: «Изменить» → строка `Srvr=…;Ref=ИМЯ`.
- Пользователь Бухгалтерии для чтения (лучше отдельный `sapar_api`, роль только на чтение) и его пароль.

## 6. Не входит
Изменение данных в Бухгалтерии, перенос оплат в УТП.
