# ТЗ: личный план ТП и акции с подарком

Версия 0.2 (19.11.2026). Статус: **утверждено заказчиком 19.11.2026**, в работе.
Решения заказчика: план по выручке 1С за месяц; акция срабатывает **один раз на заказ** (не за каждые 100); подарок с того же склада в тех же единицах; акция для всех клиентов; ТП видит текущий и прошлый месяц.
Связанные документы: TZ_MGMT_REAL_DATA.md (план продаж, «Команда»), TZ_V1.0_RU.md.

## 1. Что не так сейчас

1. Вкладка ТП «Мой план» показывает экран «Команда» (рейтинг всех ТП). У настоящего ТП сервер уже отдаёт только его самого
   (`team.own`) и менять план он не может (`plans.edit` только у владельца и директора, есть тест). Но экран похож на командный:
   «Выручка команды», «Долг клиентов», карточки с рейтингом и местами. Владелец и директор, открыв приложение ТП, видят
   всех — это и было на скриншоте от 19.11.
2. У ТП нет простого личного плана: «надо 5 000 000, закрыл 3 950 000, осталось 1 050 000, 79 %».
3. Директор вводит план по каждому ТП вручную, способа «всем одинаково» нет.
4. Акций нет совсем.

## 2. Личный план ТП

### 2.1 Что видит ТП (только своё)
- Заголовок: месяц (например «Ноябрь 2026»).
- Большая карточка: **План**, **Выполнено**, **Осталось**, **% выполнения**, полоса прогресса.
- Выполнено = выручка по клиентам этого ТП за месяц (как сейчас, данные 1С).
- Если выполнено больше плана: «Осталось» заменяется на «Сверх плана +X ₸», процент может быть больше 100 %, полоса зелёная.
- Заказы выше плана принимаются без ограничений.
- Нет списка других ТП, нет рейтинга, нет кнопки «План продаж на месяц», нет блока «Выручка команды».
- Ниже карточки личные цифры: клиенты покупали / закреплено, долг и просрочка своих клиентов, средняя выручка на клиента.
- Если план на месяц не задан: «План на месяц ещё не назначен директором».

### 2.2 Что делает директор (и владелец)
- Окно «План продаж на месяц»: выбор месяца, список ТП, у каждого своя сумма.
- Новая кнопка **«Всем одинаково»**: вводится одна сумма и подставляется всем ТП. После этого можно поправить любого.
- Кнопка **«Скопировать с прошлого месяца»**.
- Права `plans.edit` остаются только у владельца и директора. Остальные (в том числе ТП) получают 403 — уже так.

### 2.3 Сервер
- Новый `GET /api/my-plan?month=YYYY-MM` для ТП и супервайзера: `{month, plan, done, left, over, pct}` только по ТП из `users.manager_1c`.
- Владелец/директор, открывший приложение ТП: выбирает ТП из выпадающего списка (смотреть как ТП).
- `PUT /api/plans` без изменений по формату (`{month, items}`); «всем одинаково» делается на экране.

## 3. Акции с подарком

### 3.1 Смысл
Директор создаёт акцию: «купи N штук товара — получи M штук подарка». Пример: «Zigi Zagi 100 блоков + подарок 5 блоков».

### 3.2 Акция (данные)
- Название и короткая надпись (например «Zigi Zagi: 100 + 5 в подарок»).
- Период: с какого и по какое число; можно выключить вручную.
- Условие: товар из списка 1С + количество (порог).
- Подарок: товар из списка 1С + количество. Подарок берётся со склада, как обычный товар (остаток `onec_stock`); на нехватку подарка показывается предупреждение.
- Кому: все клиенты (по умолчанию).
- Повтор: нет. Подарок даётся **один раз на заказ**: набрал 100 и больше — получил 5 (при 250 блоках тоже 5).

### 3.3 Как работает в заказе
- В каталоге у товара с акцией значок «Акция» и надпись.
- Когда набрано количество не меньше порога, в заказ сама добавляется строка «Подарок: товар × M» с ценой 0 ₸ и пометкой «Акция».
- Подарочная строка идёт оператору и в 1С отдельной строкой с нулевой ценой; в сумму заказа не входит.
- Склад видит в сборочном листе «Подарок» отдельной выделенной строкой.
- Если подарка на складе не хватает: заказ принимается, подарок добавляется в размере остатка, оператор и директор получают уведомление.

### 3.4 Права и экраны
- Создавать, менять и выключать акции: владелец, директор (новое право `promos.edit`).
- Видят акции и используют: все, кто оформляет заказы (ТП, магазины), оператор, склад.
- Экран «Акции» у директора и владельца: список (активные / прошедшие), кнопка «Новая акция», выбор товаров из каталога с поиском.

### 3.5 База данных (миграция 015)
- `promos(id, title, label, active, date_from, date_to, buy_product, buy_qty, gift_product, gift_qty, repeat boolean, created_by, created_at)`.
- В `order_items` — признак `is_gift boolean` и `promo_id`.

### 3.6 Тесты
- Директор создаёт акцию; ТП не может (403).
- Заказ ниже порога — подарка нет; ровно порог — подарок; 2×порог — подарок всё равно один раз.
- Подарок нулевой по цене, не входит в сумму; склад получает строку «Подарок».
- Акция вне периода или выключенная не срабатывает.
- `GET /api/my-plan`: ТП получает только свой план; чужой через параметры получить нельзя.

## 4. Вопросы заказчику (с предложенными ответами)

1. План ТП считается по выручке из 1С за месяц — **да**
2. Акция: **один раз на заказ**
3. Подарок с того же склада и в тех же единицах (блок) — **да**
4. Акция для всех клиентов — **да**
5. ТП видит план за текущий и прошлый месяц — **да**

### 6.1 Что сделано (19.11.2026)
- Переводчик проверен автоматически: из всех экранов выписаны русские строки (около 1000), 615 непереведённых фраз добавлены в `src/00_core/kk_dictionary_more.jsx` (подключён в `modules.json` сразу после `kk_dictionary.jsx`), плюс 170 сообщений сервера (ошибки, «Проблемы», журнал заказа) и названия из 1С (типы цен, группы, статьи, кассы).
- Исправлена ошибка движка: фразы, которые начинаются или заканчиваются знаком («, просрочено», «Цены: «», «; старше 30 дней — »), не находились рядом с буквами и оставались русскими. Теперь границу слова проверяем только у буквенного края (`kkRegex` в `i18n_ru_kk.jsx`).
- Подписи в форме акции: «Действует с» / «по» → «Начало акции» / «Конец акции» (иначе слово «по» нельзя перевести отдельно).
- Текст отчёта смены для директора (WhatsApp) намеренно остаётся русским — как отправляется.
- Проверка в браузере в режиме ҚАЗ: экраны ТП (магазины, каталог, мой план), владельца (Акции, Команда, Маршруты, Магазины, Финансы, Склад, Клиенты, Система, Проблемы, Задачи, Продажи, Заказы). Без перевода остались только слова, одинаковые в казахском (оператор, директор, бухгалтер, логин, рейс, маржа и т.п.) и данные из 1С (названия товаров и магазинов).
