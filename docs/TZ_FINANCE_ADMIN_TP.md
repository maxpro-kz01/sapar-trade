## Часть B. Касса, банк, расходы, чистая прибыль

### B1. Экран «Финансы» (владелец)
| Блок | Содержание |
|---|---|
| Деньги сейчас | Остаток по каждой кассе и счёту, итого; минус подсвечен красным |
| Движение денег | За период: поступило / выплачено по дням и по группам статей; переводы между своими счетами не считаются |
| Расходы | По статьям за период, сравнение с прошлым периодом, топ-10 статей |
| P&L | Выручка − себестоимость = **валовая прибыль** − операционные расходы = **чистая прибыль**; маржа %; по месяцам |
| Статьи | Список статей движения денег из 1С и их группа; владелец может поменять группу у любой статьи |

Директор: только «Поступило денег за период». Бухгалтер: деньги и движение, без прибыли. ТП/склад/админ: ничего.

### B2. Группы статей (по умолчанию, владелец может изменить)
| Группа | Статьи из 1С (примеры) | В прибыли |
|---|---|---|
| Поступления от покупателей | 1Оплата покупателя, Оплата платежной картой | нет (выручка берётся из продаж) |
| Оплата поставщикам | Оплата поставщику | нет (уже в себестоимости) |
| Переводы между своими счетами | Деньги в пути, Зачисление кассовой выручки на расчётный счёт, Поступление с расчётного счёта, Выдача кассе ККМ | не учитываются нигде |
| Займы и кредиты | Погашение займов, Расчёты по кредитам и займам | нет, показываются отдельно |
| **Операционные расходы** | Расходы Сапар (решение 09.11), Зарплата, Доставка, ГСМ, Ремонт машины, Связь, Стоянка, Суточные, Штраф, Прочие и все новые статьи-выплаты | **да** |
| Без статьи | Движение без статьи в 1С | показываем отдельной строкой «Без статьи — уточнить в 1С» |

Новая статья, появившаяся в 1С, автоматически попадает в «Операционные расходы» (если это выплата) или «Поступления» (если приход) и видна в списке «Статьи» с пометкой «новая».

### B3. Как считается
- Выручка и себестоимость — как сейчас (регистры «Продажи», «ПродажиСебестоимость»).
- Расходы — **по оплате** (кассовый метод): выплата по статье в день выплаты. Расходы из 1С:Бухгалтерии добавятся позже (отдельное подключение).
- Чистая прибыль = валовая прибыль − операционные расходы.

### B4. Работа
1. Агент: запросы `cash` (остатки), `cashflow` (по дням × статья × приход/расход × касса/счёт), `cf_articles` (справочник статей).
2. Сервер: таблицы `onec_cash`, `onec_cashflow_daily`, `cf_article_groups` (группы статей, правка владельцем); `/api/finance` — блоки денег, движения, расходов, P&L; права.
3. Сайт: вкладка «Финансы» — 5 блоков из B1, редактор групп статей.
4. Тесты: права (директор/бухгалтер/ТП), группы, переводы не попадают в расходы, сверка сумм.
5. Сверка с бухгалтером: остатки = отчёт «Остатки денежных средств», расходы за месяц = отчёт «Движения денежных средств».

## Часть E. ТП клиентов из мобильного агента

- Агент: запрос `client_agents` — для каждого клиента ТП (`МобильныйАгент`) по его реализациям за последние 90 дней: у кого больше документов, при равенстве — у кого последний. Если агента нет — имя договора, если оно совпадает с именем одного из ТП.
- Сервер: поле «ТП» у клиента заполняется из этого запроса; клиенты без ТП — в группе «Без ТП» (видят владелец и директор).
- Сотрудники: при создании ТП владелец **выбирает его имя из списка ТП, найденных в 1С** (14 человек) — без ручного ввода и опечаток.
- Команда, план/факт, «Мои магазины» у ТП, рейтинг — начинают работать по этим данным.
- Проверка: у каждого из 14 ТП количество клиентов и продажи за месяц совпадают с отчётом «Эдванс Агент»/1С по агенту.

## Часть F. Возраст долга по документам

- Агент: запрос `debts` — долг по клиенту и **документу** (вместо пустой «Сделки»), дата документа.
- Долг без документа (начальные остатки, перенос) — группа «Без документа (старые)», считается просроченным.
- Возраст долга (0–7, 8–14, 15–30, 31–60, 61–90, 90+ дней), просрочка и проблемы — по дате документа.
- Только договоры «с покупателем» (поставщики не попадают).

## Часть D. Заказ из приложения ТП → «Реализация» в 1С (непроведённая)

### D1. Как работает
1. ТП оформляет заказ в приложении → сервер сохраняет (как сейчас).
2. Агент при каждом запуске (раз в 5 минут) забирает новые заказы и **создаёт в 1С документ «Реализация товаров и услуг», не проводит его**.
3. Оператор в 1С проверяет и проводит. В приложении у заказа видно: «в 1С № 00000033001» или ошибку.

### D2. Что заполняется в документе
| Поле 1С | Значение |
|---|---|
| Дата | Время заказа |
| Организация | ИП Сапар |
| Контрагент | Клиент заказа (по коду) |
| Договор | Основной договор клиента |
| Склад | Основной склад |
| Тип цен | «Цена Прайс» |
| Валюта | KZT |
| Вид операции | «Продажа, комиссия» (как в текущих реализациях) |
| Комментарий | «Sapar Trade СТ-000123 · ТП Имя · комментарий ТП» |
| Товары | Номенклатура (по коду), количество, единица (базовая), цена и сумма из приложения, ставка НДС из номенклатуры |

### D3. Безопасность
- Документ **только записывается, не проводится** — остатки и долги в 1С не меняются, пока оператор не проведёт.
- Защита от дублей: номер «СТ-…» в комментарии; перед созданием агент ищет такой документ.
- Переключатель в админ-панели → «Настройки»: «Отправлять заказы в 1С» — по умолчанию **выключен**; включаем после проверки. Заказы, сделанные при выключенной отправке, в 1С сами не уходят — их можно отправить кнопкой «Отправить в 1С» в заказе.
- Проверка без последствий: `5_check-orders.bat` — реализация по образцу последней продажи записывается в транзакции и сразу отменяется.
- Пользователю `sapar_api` нужно **право записывать документ «Реализация товаров и услуг»** — см. вопрос 2. Остальное остаётся только для чтения.
