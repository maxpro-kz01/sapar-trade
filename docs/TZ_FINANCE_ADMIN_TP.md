# ТЗ: деньги и прибыль из 1С + админ-панель и приложение ТП на реальных данных

Версия 1.1 · 28.10.2026 · статус: **часть C (экраны) сделана; часть B и запись в 1С — после диагностики №3**

### Решения заказчика (28.10.2026)
- Расходы частично ведутся в **1С:Бухгалтерии** → нужно второе подключение (имя сервера и базы — уточняется).
- Заказы ТП создаются в 1С сразу, документом **«Реализация товаров и услуг» (непроведённая)** — так в базе работают сейчас («Заказ покупателя» не используется: 0 за неделю, реализаций 751).
- Сейчас ТП работают в «Эдванс Агент»; наше приложение ТП — параллельно.
- «Реклама», «Истории», «CRM» скрыты до запуска приложения для магазинов (код — `src/_prototype`).
- Цена в каталоге ТП — «Цена Прайс».

### Находки диагностики №2
- «Основной менеджер покупателя» пуст у всех 8329 клиентов → ТП берём из реализаций (`орда_ТорговыйПредставитель`) / имени договора (диагностика №3).
- Деньги: `ДенежныеСредства` (8 касс/счетов), `ДвиженияДенежныхСредств` (статьи, приход/расход). Регистра `Затраты` нет → расходы УТП = выплаты по статьям ДДС (классификация статей — диагностика №3).
- Долги: поле «Сделка» пустое → возраст долга по полю «Документ» (диагностика №3).

Две части, делаются по очереди: **часть B** (деньги и прибыль) и **часть C** (админ-панель и ТП).

## Часть B. Касса, банк, расходы, чистая прибыль

### B1. Что показываем (вкладка «Финансы», только владелец)
| Блок | Содержание |
|---|---|
| Деньги сейчас | Остаток в каждой кассе и на каждом банковском счёте, итого |
| Движение денег за период | Поступления и выплаты по дням; по статьям движения денежных средств (оплата покупателей, оплата поставщикам, зарплата, аренда, налоги…) |
| Расходы | Расходы за период по статьям; сравнение с прошлым периодом |
| P&L (прибыль и убытки) | Выручка − себестоимость = валовая прибыль − расходы = **чистая прибыль**; маржа валовая и чистая; по дням и по месяцам |
| Директор | Видит только «Поступило денег за период» (по ТЗ V1.0 §4), без расходов и прибыли |
| Бухгалтер | Касса и банк (остатки и движение), без прибыли |

### B2. Откуда в 1С (УТП 2.0, типовые имена — сверяем диагностикой `-Probe`)
| Данные | Объект 1С |
|---|---|
| Остатки денег | РегистрНакопления.ДенежныеСредства (касса/банковский счёт, сумма) |
| Поступления/выплаты по статьям | РегистрНакопления.ДвиженияДенежныхСредств (приход/расход, статья ДДС, сумма) |
| Расходы | РегистрНакопления.Затраты и/или ПрочиеДоходыИРасходы (статья затрат, сумма) |

**Важно.** Чистая прибыль будет правильной только если **все расходы ведутся в этой базе УТП**. Если зарплата, аренда, налоги ведутся в 1С:Бухгалтерии или в Excel, их здесь не будет — нужно решить (вопрос 1).

### B3. Работа
1. Агент: расширить диагностику (`-Probe`) — список всех регистров базы и структура денежных регистров; вы запускаете и присылаете файл.
2. По файлу пишу 3 новых запроса: `cash` (остатки), `cashflow` (движение по дням и статьям), `expenses` (расходы по дням и статьям).
3. Сервер: таблицы `onec_cash`, `onec_cashflow_daily`, `onec_expenses_daily`; отчёты `/api/finance` (расширение), `/api/cash`; права как выше.
4. Сайт: вкладка «Финансы» — блоки «Деньги», «Движение денег», «Расходы», «P&L».
5. Сверка с бухгалтером: остатки денег и расходы за месяц = отчётам 1С.

## Часть C. Админ-панель и приложение ТП на реальных данных

### C1. Вход
- Администратор и ТП входят **по личному логину и паролю** (как в Системе управления). Демо-пароли `admin/admin` и `agent/agent123` убираются.
- Учётки ТП создаёт владелец/администратор; у ТП указывается его имя-менеджер в 1С.

### C2. Приложение ТП
| Экран | Что меняется |
|---|---|
| Мои магазины | Клиенты из 1С, у которых ТП — «Основной менеджер покупателя»: долг, просрочка, последняя покупка |
| Заказ по магазину | Каталог из 1С: товары, группы, **цены** (тип цен клиента/«Цена Прайс»), **остатки**; корзина |
| Мои заказы | Заказы хранятся на сервере, статусы |
| Мой план | План/факт за месяц (из «Команды») |

### C3. Админ-панель
| Раздел | Что меняется |
|---|---|
| Смена | Начать/завершить работу на сервере; отчёт за день — **реальные цифры** (продажи из 1С за день, заказы из приложения, долги, остатки «заканчивается»); отправка директору в WhatsApp |
| Заказы | Заказы ТП (и клиентов, когда запустим клиентское приложение) с сервера: принять → передать на склад → собран → отгружен |
| Склад | Остатки и цены из 1С (только просмотр — правятся в 1С) |
| Сотрудники | Учётки ТП и других сотрудников (те же, что в Системе управления) |
| Реклама, Истории, CRM, Настройки | Относятся к клиентскому приложению; переводим вместе с ним (отдельный этап) или скрываем до запуска |
| Аудит | Журнал действий с сервера |

### C4. Заказы и 1С
- Этап C (сейчас): заказы живут в приложении (сервер), администратор видит и ведёт их; в 1С менеджер вводит вручную по распечатке/списку.
- Этап D (потом, после 2 недель стабильной работы): агент сам создаёт в 1С **«Заказ покупателя» (непроведённый)**, менеджер проверяет и проводит. Для этого пользователю `sapar_api` нужно право создавать только этот документ.

### C5. Критерии приёмки
- В админ-панели и приложении ТП нет придуманных цифр и демо-паролей.
- ТП видит только своих клиентов и не видит себестоимость/маржу.
- Заказ ТП появляется у администратора без перезагрузки страницы (обновление раз в 30 секунд) и сохраняется после перезапуска сервера.
- Отчёт смены совпадает с 1С за тот же день.

## Порядок работ
1. **B1–B2:** новая диагностика агента → вы присылаете probe.
2. Пока ждём probe — **C** (вход, ТП, заказы, админ-панель, смена).
3. **B3–B5:** запросы денег и расходов, экран «Финансы».

## Вопросы
1. Где ведутся расходы (зарплата, аренда, топливо, налоги): в этой базе УТП, в 1С:Бухгалтерии или в другом месте?
2. Заказы ТП: пока только в приложении (менеджер вводит в 1С вручную) или сразу делать создание «Заказа покупателя» в 1С?
3. Разделы админки «Реклама», «Истории», «CRM» (для клиентского приложения): скрыть до запуска приложения для магазинов или оставить?
4. Какую цену показывать ТП в каталоге: «Цена Прайс» для всех или тип цен из договора клиента (в 1С у договора есть «Тип цен»)?
