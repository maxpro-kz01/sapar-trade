# ТЗ: установка приложения, вход «пока сам не выйдешь», цены ТП по договору клиента

Версия 1.0 · 17.11.2026 · статус: **ждёт согласования**

## Часть A. Установить приложение на телефон и компьютер (PWA)

**Сейчас:** сайт открывается только в браузере, своей иконки нет.

**Сделать:**
1. `manifest.webmanifest`: название «Sapar Trade», иконки 192/512 и maskable, цвет темы, запуск в отдельном окне без строки адреса (`display: standalone`), стартовая страница `/`.
2. `sw.js` (service worker): кэширует только оболочку приложения (страницу и React), поэтому оно быстро открывается и показывает «нет интернета» вместо белого экрана. **Данные (продажи, долги, заказы) не кэшируются**, всегда берутся свежие с сервера. Новая версия подхватывается сама, вместе с уже существующей плашкой «Доступна новая версия».
3. Кнопка **«Установить приложение»** на экране входа и в меню:
   - **Android, Chrome на компьютере, Edge:** системное окно установки, иконка появляется на рабочем столе или главном экране;
   - **iPhone:** подсказка с картинкой «Поделиться → На экран "Домой"» (Apple не даёт кнопку установки);
   - уже установленное приложение кнопку не показывает.
4. Иконки: временно буквы «ST» в фирменном цвете. Когда будет настоящий логотип (PNG или SVG), заменю.

## Часть B. Вход один раз, без выхода, пока сам не выйдешь

**Сейчас (причина):** вход хранится только до закрытия вкладки (`sessionStorage`), а пропуск (токен) живёт 12 часов. Поэтому программа каждый раз просит пароль.

**Сделать:**
1. **Пара токенов:**
   - короткий токен доступа на 1 час;
   - долгий токен входа на **90 дней**, который продлевается при каждом использовании. Если человек заходит хотя бы раз в 90 дней, программа не выкидывает его никогда.
2. Токен входа хранится в памяти телефона или компьютера (`localStorage`) и переживает закрытие браузера, перезагрузку и установку приложения. На сервере хранится только его хэш, в таблице `sessions` (миграция 008): кто, устройство, когда вошёл, когда последний раз был.
3. Токен доступа обновляется сам, незаметно. При каждом обновлении выдаётся новый токен входа, старый перестаёт работать. Если украденный старый токен попробуют использовать, все входы этого человека закрываются.
4. **Выход:**
   - кнопка «Выйти» закрывает вход на этом устройстве;
   - владелец в «Сотрудниках» может «Выйти на всех устройствах» за сотрудника, например при увольнении или потере телефона;
   - блокировка или удаление сотрудника сразу закрывает все его входы;
   - смена пароля закрывает входы на других устройствах.
5. Список «Мои устройства» в профиле: где вход открыт, когда был последний раз, кнопка «Закрыть».

## Часть C. ТП: товары «неактивные» при заказе

**Причина:** цену товара сайт берёт из одного типа цен на всех. Тип выбирается автоматически: тот, у которого больше всего строк в 1С. В базе 14 типов цен (АЗС, Вансел, Область, Рынок, Себестоимость, Цена Прайс, Цены магазин…). Если у товара нет цены выбранного типа, строка бледная, без кнопки «+». При этом заказ в 1С уходит по типу «Цена Прайс». **Цены на сайте и в 1С могут не совпадать, это ошибка.**

**Сделать:**
1. Агент: в выгрузку клиентов добавить тип цен из основного договора клиента (`ОсновнойДоговорКонтрагента.ТипЦен`).
2. Сервер: каталог ТП строится **для конкретного магазина**, по типу цен его договора. Если у договора тип не указан, берётся «Цена Прайс» (настраивается).
3. 1С: реализация по заказу создаётся с тем же типом цен, что видел ТП. Цены на сайте и в 1С совпадают.
4. Товар с остатком, но без цены: строка бледная с подписью «нет цены для типа "…"», чтобы было понятно, что исправлять в 1С. Счётчик «без цены: N» вверху.
5. Тесты: два магазина с разными типами цен видят разные цены; заказ сохраняет тип цен.

## Часть D. Долги «ничего не изменилось»

**Причина:** сервер уже обновлён и готов брать долги из Бухгалтерии. Но пока на сервере 1С не запущен `8_buhgalteria.bat`, данные из Бухгалтерии не приходят, и сайт, как задумано, показывает долги из УТП.
**Нужно от заказчика:** запустить `agent-update.bat`, потом `8_buhgalteria.bat` (имя базы Бухгалтерии, пользователь, пароль) и прислать фото окна.
**Дополнительно в этой задаче:** в УТП у контрагента есть БИН/ИИН (`ИдентификационныйКодЛичности`). Сопоставлять с Бухгалтерией сначала по БИН/ИИН, потом по названию. Так меньше магазинов останется «не найденными».

## Порядок и проверка
C → B → A → D. Тесты сервера по каждой части. Проверка в браузере (Playwright) на телефоне и компьютере: установка, вход после перезапуска браузера, выход, заказ ТП.
